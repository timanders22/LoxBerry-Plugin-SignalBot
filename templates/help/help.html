Dieses Plugin macht aus Signal eine Fernbedienung für das Haus: Befehle per Chat an den Miniserver, Meldungen aus Loxone zurück in den Chat. Beide Richtungen.

Reihenfolge beim Einrichten:

  1. Einstellungen → Verknüpfung starten. Der QR-Code wird am Handy unter Signal → Einstellungen → Gekoppelte Geräte gescannt. Der Bot hängt sich als Zweitgerät an das eigene Konto, eine zweite Rufnummer braucht es nicht.
  2. Die erlaubten Absender eintragen — eine Rufnummer je Zeile. Wer nicht daraufsteht, bekommt keine Antwort.
  3. Eine PIN vergeben, wenn kritische Befehle geplant sind.
  4. Befehle → die Tabelle füllen. Je Zeile: das Wort, das MQTT-Thema und die Stufe.
  5. MQTT → das Abo ins Gateway eintragen. Ohne diesen Eintrag kommt am Miniserver nichts an.
  6. Einbindung in Loxone → virtuelle Eingänge auf die Themen legen und die Adresse für Meldungen kopieren.
  7. Test → Selbstprüfung ansehen und einen Befehl trocken durchspielen.

Zu den Stufen: Sofort führt ohne Rückfrage aus. Rückfrage lässt den Bot nachfragen. PIN verlangt zusätzlich die PIN. Für Alarmanlage und Haustür gehört die Stufe PIN.

Wenn nichts ankommt: Der Reiter Test geht die Kette von unten nach oben durch — ist signal-cli installiert, ist Java neu genug, passt die native Bibliothek zur Architektur, läuft der Dienst, antwortet die Schnittstelle, ist ein Konto verknüpft, lauscht der Bot. Der erste Kreuz-Eintrag ist meist die Ursache.

Auf dem Raspberry Pi: signal-cli bringt seine native Bibliothek nur für x86_64 mit. Auf ARM muss sie getrennt beschafft werden, oder signal-cli läuft in einem Docker-Abbild mit ARM-Unterstützung und das Plugin bindet nur dessen Adresse ein.
